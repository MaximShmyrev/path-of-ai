# Путь ИИ

**Концепция:**
РПГ игра для геймификации изучения ИИ. Должна отображать прогресс и дорожную карту обучения в стиле олдскульных RPG (Diablo, Dungeon Siege, Dragon Age). Эталон визуала — **Diablo II / D2R**: полноэкранный иммерсивный интерфейс, готическое тёмное фэнтези, нижняя HUD-панель со сферами (орбами) и поясом героя, орнаментальные рамки, атмосфера (виньетка, угольки). Игра не «приклеивает очки к курсу», а **учит**: каждая тема сначала объясняет материал, затем закрепляет практикой с разбором.

**Ключевые правила:**

- Проект должен представлять собой фронтенд и бэкенд, запускаться в docker compose, на современном технологическом стеке
- Всё взаимодействие с пользователем должно быть выдержано в стиле RPG-игр, для генерации персонажей, картинок, элементов интерфеса мы можем использовать claude designer, ставь мне задачи для этого
- **Реальное обучение, а не викторина.** Каждая тема обязана содержать обучающий материал (урок/«свиток теории»: объяснение концепции + пример + ключевые тезисы), который пользователь читает ДО проверки. Практика (квиз/испытание) даёт **разбор**: почему ответ верный/неверный. Цель — научить ИИ-технологиям, а не просто заставить угадывать варианты.
- **LLM-наставник (гибрид).** Поверх курируемого урока — наставник-NPC на базе LLM для углубления и ответов на вопросы по теме; при недоступности LLM работает детерминированный фолбэк.
- **Иммерсивный полноэкранный UI в каноне Diablo II.** Игра занимает весь экран; нижняя HUD-панель (орбы прогресса + пояс героя), орнаментальные рамки/свитки, дьябло-шрифты с поддержкой кириллицы, атмосферные эффекты. Чем ближе к ощущению настоящей игры — тем лучше.
- **Полноценные RPG-механики, и все визуализированы.** Это не «карта с квизами», а игра: **дерево навыков**, **инвентарь героя** (артефакты/лут), **квесты**, **сражения** (босс-бои), **карта мира**, сквозной **сюжет**. Каждая механика служит обучению (навыки = освоенные компетенции ИИ, артефакты = справочники/инструменты/трофеи, бой = применение знаний) и имеет полноценный игровой экран, а не текстовую заглушку.
- **Карта мира в духе Средиземья (ВК/Хоббит).** Континент с именованной географией (хребты, реки, леса, топи, тракты, крепости); регионы = земли, темы = названные локации, квесты проходят в них. Лор и нейминг — `WORLD.md` (имена оригинальные, не из IP Толкина).

**Строгие требования (соблюдай неукоснительно):**

- Строго соответствуй правилам выше и гайду.
- После выполнения задачи **запускай тесты** и **делай статический анализ**
  (линтер + строгая типизация).
- Следуй практике **TDD**. Я хочу видеть **упавшие тесты в начале работы** и
  только потом код, выполняющий работу. Используй **skill `tdd`**.
- Двигайся небольшими итерациями; не выдавай незавершённое за готовое.

**Развёрнутое описание проекта и его целей:**
Мы делаем обучающую платформу, которая будет мотивировать меня учиться ИИ-технологиям каждый день за счёт геймификации. Это должно быть аналогично прохождению онлайн-курсов или обучению в университете, но с большим упором на практику: любая тема должна содержать практическое применение. Ролевой сюжет, события, карта игровой вселенной и взаимодействие с игровым миром должны быть продуманы и динамичны, возможно использование LLM для генерации по ходу прохождения. Также мы должны соответствовать канону олдскульных RPG, но весь интерфейс должен быть на русском (за исключением специальных терминов из тем обучения). Чем ближе мы будем к популярным RPG по стилю, графике и атмосфере — тем лучше.

**Доменная модель (термины игрового мира):**

- **Герой (персонаж)** — профиль обучающегося: уровень, опыт (XP), характеристики, инвентарь.
- **Карта мира / дорожная карта** — визуализация программы обучения ИИ в стиле карт Средиземья (ВК/Хоббит): именованная география (континент, хребты, реки, леса, топи, тракты, крепости), где регионы = земли (ML, LLM, RAG, агенты), а темы = названные локации внутри них. Квесты проходят в этих локациях ради ощущения классической RPG. Лор и нейминг — в `WORLD.md` (мир-библия); имена оригинальные, каждое намекает на концепцию ИИ.
- **Локация / подземелье** — отдельная тема обучения внутри региона.
- **Урок / свиток теории** — обучающий материал темы: объяснение концепции, пример, ключевые тезисы. Читается до практики; это «сердце» обучения, а не формальность.
- **Квест** — учебное задание внутри темы; обязательно содержит практическую часть и **разбор ответа** (объяснение, почему верно/неверно).
- **Наставник (NPC)** — проводник-LLM: отвечает на вопросы по теме и углубляет урок; имеет детерминированный фолбэк без LLM.
- **Босс / сражение** — итоговая проверка темы в формате боя: испытание (серия вопросов/мини-проект), визуализированное как combat (полоски здоровья, раунды/ходы; верные ответы «бьют» босса, ошибки «бьют» героя). Победа = освоение темы.
- **Дерево навыков (skill tree)** — визуальная карта компетенций ИИ: узлы-навыки открываются прохождением тем/боссов, с пререквизитами и ветками; показывает, что герой реально освоил.
- **Инвентарь героя** — визуальная сетка собранных **артефактов/лута**: значки, открытые инструменты, справочные карточки (cheat-sheets по темам), трофеи боссов; предметы имеют описание и обучающую ценность.
- **Сюжет** — сквозная нарративная линия, связывающая регионы и темы; динамические события и реплики наставника генерируются LLM по ходу прохождения (с фолбэком).
- **Опыт и уровни** — прогресс обучения; за уроки/квесты/боссов даётся XP, уровень открывает новые регионы, узлы навыков и слоты инвентаря.

**Границы задачи (что НЕ входит в первую версию):**

- Мультиплеер, PvP, соцфункции — не входят.
- Платежи/монетизация — не входят.
- Мобильные приложения (native) — не входят; только веб (адаптивная вёрстка допустима).
- Реальная проверка кода ученика выполнением (sandbox-исполнение) — вне MVP; начинаем с тестов/самопроверки.

**Сценарии пользователя (BDD, Given / When / Then):**

- Сценарий: Создание героя
  - Дано пользователь впервые открыл приложение и не имеет персонажа
  - Когда он проходит создание героя (имя, класс/специализация, стартовый аватар)
  - Тогда создаётся персонаж 1-го уровня с 0 XP, и он попадает на карту мира с одним открытым стартовым регионом
- Сценарий: Просмотр карты мира и дорожной карты обучения
  - Дано у пользователя есть персонаж
  - Когда он открывает карту мира
  - Тогда он видит регионы (области ИИ), доступные/заблокированные локации и свой текущий прогресс в RPG-стиле
- Сценарий: Изучение урока (теория темы)
  - Дано пользователь вошёл в доступную локацию (тему)
  - Когда он открывает «свиток теории»
  - Тогда он видит полноценный обучающий материал (объяснение концепции + пример + ключевые тезисы), оформленный в RPG-стиле; после прочтения урок отмечается изученным и начисляется XP
- Сценарий: Прохождение квеста (с практикой и разбором)
  - Дано пользователь вошёл в доступную локацию (тему) и изучил урок
  - Когда он выполняет учебный квест и отправляет практическое задание на проверку
  - Тогда при успехе начисляется XP, квест отмечается завершённым, прогресс темы обновляется; в любом случае показывается **разбор** — объяснение, почему ответ верный/неверный
- Сценарий: Вопрос наставнику (LLM-углубление)
  - Дано пользователь находится в теме и хочет глубже разобраться
  - Когда он задаёт вопрос наставнику-NPC
  - Тогда наставник отвечает по теме в каноне RPG на русском (через LLM); при недоступности LLM срабатывает детерминированный фолбэк, и пользователь всё равно получает осмысленный ответ
- Сценарий: Сражение с боссом темы
  - Дано пользователь изучил урок и прошёл практику темы
  - Когда он начинает босс-испытание
  - Тогда оно идёт как визуальный бой (полоски здоровья героя/босса, раунды): верные ответы наносят урон боссу, ошибки — герою; при победе тема считается освоенной, начисляется XP и падает трофей/артефакт
- Сценарий: Дерево навыков
  - Дано герой прошёл часть тем и боссов
  - Когда он открывает дерево навыков
  - Тогда он видит визуальный граф компетенций ИИ: открытые/закрытые узлы, пререквизиты и ветки, и понимает, что уже освоено и что откроется дальше
- Сценарий: Инвентарь героя
  - Дано герой получил награды за уроки/квесты/боссов
  - Когда он открывает инвентарь
  - Тогда он видит визуальную сетку артефактов (значки, открытые инструменты, справочные карточки, трофеи) с описанием и обучающей ценностью каждого предмета
- Сценарий: Повышение уровня и разблокировка контента
  - Дано накопленный XP достиг порога следующего уровня
  - Когда квест завершён и XP начислен
  - Тогда уровень героя повышается, проигрывается RPG-событие/анимация, и открывается новый регион или локация (а также новые узлы дерева навыков)
- Сценарий (негативный): Доступ к заблокированной локации
  - Дано локация требует уровня выше текущего или незавершённой пререквизит-темы
  - Когда пользователь пытается в неё войти
  - Тогда вход запрещён, и показывается RPG-сообщение с условиями разблокировки
- Сценарий (граничный): Сохранение и восстановление прогресса
  - Дано пользователь прошёл часть квестов и закрыл вкладку
  - Когда он возвращается и снова открывает приложение
  - Тогда весь прогресс (уровень, XP, статусы квестов) восстановлен без потерь
- Сценарий: Динамическая генерация события через LLM
  - Дано пользователь находится в локации, поддерживающей сюжетные события
  - Когда срабатывает игровое событие
  - Тогда LLM генерирует текст события в каноне олдскульной RPG на русском, и оно встраивается в текущий контекст прохождения

**Как будет проверяться результат (измеримые критерии):**

- Проект целиком поднимается одной командой `docker compose up` (фронтенд + бэкенд + БД), без ручных шагов.
- Покрытие тестами бизнес-логики бэкенда (начисление XP, уровни, разблокировки, статусы квестов) — не ниже 80% строк; ключевые расчётные функции — 100%.
- 0 ошибок линтера и 0 ошибок типов (строгая типизация) во фронтенде и бэкенде.
- Все BDD-сценарии выше покрыты автоматическими тестами (минимум один тест на сценарий, включая негативный и граничный).
- API имеет автотесты на корректность правил прогресса (нельзя «намухлевать» XP/уровень в обход правил — проверяется на уровне сервера, не клиента).
- Весь пользовательский интерфейс на русском (кроме спец-терминов); проверяется ревью UI-строк.
- Каждая учебная тема в данных содержит хотя бы один практический квест (валидируется на уровне контент-схемы/тестом).
- **Каждая тема содержит непустой обучающий урок** (теория с объяснением и примером); пустой/отсутствующий урок — ошибка валидации контента (проверяется тестом).
- **Каждый вопрос квиза имеет разбор** (explanation), который показывается после ответа; отсутствие разбора — ошибка валидации (проверяется тестом).
- **Наставник-LLM имеет детерминированный фолбэк**: при отсутствии ключа/ошибке ответ всё равно осмысленный (покрыто тестом, как у генерации событий).
- **Иммерсивность UI**: приложение работает в полноэкранном режиме (HUD со сферами и поясом героя, орнаментальные рамки, дьябло-шрифты с кириллицей); визуальный канон Diablo II проверяется ревью UI.
- **RPG-механики визуализированы, не заглушки**: дерево навыков, инвентарь, бой с боссом, карта мира и сюжетные события имеют полноценные игровые экраны. Каждая механика покрыта тестами на корректность данных (узлы навыков отражают реальный прогресс; инвентарь — реально полученные награды; бой — серверные правила урона/победы, без «мухлежа» на клиенте).
- **Именованная география карты**: каждый регион и тема имеют лор-локацию из `WORLD.md` (название + описание); карта мира визуализирует континент в стиле Средиземья. Полнота лора (нет безымянных регионов/тем) проверяется тестом контент-схемы.
