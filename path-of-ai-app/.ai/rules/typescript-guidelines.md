# TypeScript Guidelines (скелет)

Язык-специфичные правила для TypeScript-проектов. Дополняет ядро
[`styleguide.md`](styleguide.md). Заполни/удали под свой проект.

> Это скелет-пример. Для Python используется заполненный
> [`python-guidelines.md`](python-guidelines.md) как образец глубины проработки.

## Критические правила

- **Строгий режим.** `tsconfig.json` с `"strict": true`. Дополнительно:
  `noUncheckedIndexedAccess`, `noImplicitOverride`, `exactOptionalPropertyTypes`.
- **Запрещён `any`.** Используй `unknown` + сужение типов. `// @ts-ignore` и
  `// @ts-expect-error` — только с обоснованием в комментарии.
- **Fail fast.** Не глотай ошибки: никаких пустых `catch {}`. Лови конкретные
  ошибки; если ловишь широко — пробрасывай дальше после логирования.
- **Никаких неявных побочных эффектов** на уровне модуля.

## Анти-паттерны (флагать в ревью)

- `as` для приведения там, где нужно сужение через type guard.
- Мутация входных аргументов (функции должны быть предсказуемы).
- `==` вместо `===` (кроме `== null` для проверки null/undefined одновременно).
- `Promise` без `await`/`.catch` (необработанный rejection).
- Числовые `enum` там, где достаточно union строк (`type T = 'a' | 'b'`).

## Стиль

- Именование: `camelCase` — переменные/функции, `PascalCase` — типы/классы,
  `UPPER_SNAKE` — константы-конфиг.
- Предпочитай `type` и дискриминируемые union'ы; `interface` — для расширяемых
  контрактов.
- Чистые функции и неизменяемость по умолчанию (`readonly`, `const`).

## Инструменты

```bash
tsc --noEmit            # строгая проверка типов, 0 ошибок
eslint . --fix          # линтер с авто-фиксом
prettier --write .      # форматирование
vitest run --coverage   # тесты + покрытие (или jest)
stryker run             # мутационное тестирование
```

## Definition of Done (язык-специфичная часть)

- [ ] `tsc --noEmit` — 0 ошибок.
- [ ] `eslint` — 0 ошибок.
- [ ] `prettier --check` — без диффов.
- [ ] Нет `any` / `@ts-ignore` без обоснования.
