# Свой раннер на Mac mini: что сделать

Инструкция для машины, на которую будет ставиться раннер. Все команды выполняются **на ней**, не на машине разработки.

## Сначала — риск, из-за которого стоит остановиться

**Репозиторий `MaximShmyrev/path-of-ai` публичный.** Self-hosted раннер на публичном репозитории — известная дыра: любой человек может форкнуть репозиторий, открыть pull request с изменённым workflow и получить **выполнение произвольного кода на твоей машине**. GitHub прямо не рекомендует эту связку для публичных репозиториев.

Варианты по убыванию безопасности:

1. **Сделать репозиторий приватным** — риск исчезает целиком. Если публичность не нужна, это самый честный вариант: одна настройка вместо постоянной бдительности.
2. **Оставить публичным и закрыться настройками** (см. раздел «Обязательные настройки» — их нельзя пропускать).
3. Не ставить раннер вообще и деплоить с самой машины по расписанию — раздел «Альтернатива без раннера» в конце.

Дальше инструкция исходит из того, что выбран вариант 1 или 2.

## Шаг 1. Подготовить машину

Нужен Docker — деплой поднимает контейнер. Проверить:

```bash
docker version
docker compose version
```

Если Docker Desktop не стоит — поставить и **включить автозапуск при входе**, иначе после перезагрузки деплой упадёт.

Важно про macOS: раннер работает от твоего пользователя. Docker Desktop поднимается только когда пользователь залогинен — если Mac mini перезагрузится и никто не войдёт в систему, деплой встанет. Для постоянной работы включи автоматический вход в систему (Системные настройки → Пользователи и группы → Параметры входа).

## Шаг 2. Установить раннер

Не копируй версию из интернета — GitHub показывает актуальную команду вместе с одноразовым токеном:

**Settings → Actions → Runners → New self-hosted runner**, платформа **macOS**, архитектура **ARM64**.

Страница выдаст три блока команд. Выполни их на Mac mini по порядку:

1. **Download** — создаёт папку `actions-runner`, качает архив, распаковывает.
2. **Configure** — `./config.sh --url https://github.com/MaximShmyrev/path-of-ai --token ...`

   На вопросы отвечай так:
   - `Enter the name of the runner group` → Enter (Default)
   - `Enter the name of this runner` → `macmini`
   - `Enter any additional labels` → **`macmini`** — по этой метке workflow будет его выбирать
   - `Enter name of work folder` → Enter (`_work`)

3. **Не запускай `./run.sh`** из третьего блока — он живёт только пока открыт терминал. Вместо него поставь службу:

```bash
cd actions-runner
./svc.sh install
./svc.sh start
./svc.sh status
```

Служба переживает выход из сессии и перезагрузку.

Токен из блока Configure действует час. Если протух — просто обнови страницу, там будет новый.

## Шаг 3. Проверить, что раннер виден

На машине разработки:

```bash
gh api repos/MaximShmyrev/path-of-ai/actions/runners --jq '.runners[] | "\(.name) \(.status) \(.labels[].name)"'
```

Должно появиться `macmini online ... macmini`.

## Шаг 4. Обязательные настройки (если репозиторий остаётся публичным)

Без них шаг 2 открывает дыру.

**Settings → Actions → General:**

- **Fork pull request workflows from outside collaborators** → выбрать **«Require approval for all external contributors»**. Иначе PR от постороннего запустится сам.
- **Workflow permissions** → «Read repository contents permission» (уже так).

**Правило, которое надо держать в голове:** на своём раннере должен крутиться **только деплой с ветки main**, и никогда — сборка кода из pull request. CI (тесты, валидатор) остаётся на `ubuntu-latest`: он ничего не деплоит и пусть гоняется у GitHub.

## Шаг 5. Переписать деплой под свой раннер

Сейчас `.github/workflows/deploy-rpg.yml` ходит по SSH с раннера GitHub на твой сервер и требует пять секретов: `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`, `DEPLOY_PATH`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Ни один не задан — поэтому все три прогона упали за пять секунд на первом же шаге проверки.

Со своим раннером **SSH и все эти секреты не нужны вообще**: раннер уже стоит на целевой машине, ему достаточно поднять контейнер из своей рабочей копии.

Замена workflow (могу применить сам — скажи):

```yaml
name: Deploy AI Agents RPG

on:
  push:
    branches: [main]

permissions:
  contents: read

concurrency:
  group: production-rpg
  cancel-in-progress: false

jobs:
  deploy:
    # Только push в main. На pull_request не запускается никогда —
    # это защита от выполнения чужого кода на своей машине.
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: [self-hosted, macmini]
    timeout-minutes: 10

    steps:
      - uses: actions/checkout@v4

      - name: Поднять контейнер
        run: docker compose up -d --build --remove-orphans

      - name: Проверить, что отвечает
        run: |
          set -euo pipefail
          for i in $(seq 1 30); do
            curl -fsS http://127.0.0.1:8789/ >/dev/null 2>&1 && exit 0
            sleep 2
          done
          docker compose logs --tail 50
          exit 1
```

Что изменилось по сути:
- `runs-on: [self-hosted, macmini]` вместо `ubuntu-latest`;
- убраны шаги настройки SSH и удалённого выполнения — контейнер поднимается локально;
- смоук-проверка бьёт в `127.0.0.1:8789` уже на самой машине;
- добавлен явный `if`, запрещающий запуск где-либо кроме push в main.

После этого `/opt/path-of-ai` не нужен: раннер держит рабочую копию у себя в `_work`.

## Шаг 6. Проверить

Смержить PR в main или нажать **Re-run** на последнем прогоне Deploy. Ожидаемо: раннер подхватывает задание, собирает образ, контейнер отвечает на `http://127.0.0.1:8789/` уже на Mac mini.

## Полезные команды

```bash
cd actions-runner
./svc.sh status     # состояние службы
./svc.sh stop       # остановить
./svc.sh uninstall  # снять службу
./config.sh remove --token <токен снятия>   # отвязать раннер от репозитория
```

Логи заданий — в `actions-runner/_diag/`.

## Альтернатива без раннера

Если ставить агент, исполняющий код из GitHub, не хочется, есть вариант без входящих соединений и без раннера: на Mac mini повесить `launchd`-таймер, который раз в N минут делает `git fetch`, и если на `origin/main` появился новый коммит — `git checkout` и `docker compose up -d --build`.

Плюсы: ничего не слушает извне, GitHub не исполняет ничего на твоей машине, публичность репозитория перестаёт быть проблемой.
Минусы: деплой не мгновенный, а в пределах интервала опроса, и в интерфейсе GitHub его не видно.
