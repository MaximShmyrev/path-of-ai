Сначала **пойми, как задача должна работать** — проговори логику работы системы
перед планированием.

Затем **составь план** и сохрани его в `PLAN.md`.

Требования к плану:

- План состоит из **этапов**, каждый из которых можно выполнить **без
  переполнения контекста** (один этап = один обозримый объём работы).
- Каждый этап содержит **оценку выполнения** (трудоёмкость/время и критерий
  завершения этапа).
- В начале плана, **в первых 200 строках**, — контекст проекта и **индекс
  плана** (список этапов со ссылками).
- В **конце файла** — **changelog выполненных задач** (пополняется по ходу
  работы).
- План следует подходу **TDD**: внутри каждого этапа сначала тесты (RED), затем
  реализация (GREEN), затем рефакторинг. Используй **skill `tdd`**.
- Каждый этап явно ссылается на сценарии тестов и количественные критерии из
  спецификации, которые он закрывает.

Учитывай мои правила и гайды по стилю (`@Styleguide` + язык-специфичный гайд).

Порядок этапов должен минимизировать риск: сначала тонкий сквозной срез (tracer
bullet), затем наращивание.
